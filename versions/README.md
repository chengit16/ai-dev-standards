# 版本与兼容

工具包通过 Git 标签发布版本，首发版本为 `v0.1.0`。参考来源按公开范围留存，生成清单通过工具包提交和内容指纹记录规范版本。

M3 生成的 `manifest.json` 使用 `schema_version: 1`，记录工具包 Git 提交、相关工作树状态，以及所采用规范和入口模板的 SHA-256 内容集合指纹。来自未提交工作树的生成物是可校验的内容快照，不等同于该 Git 提交的完整发布版本。

业务项目通过 `project.json` 保存选择、检查与差异。重复初始化只允许内容一致，工具包升级不会自动修改既有项目。已有项目可使用 [upgrade-rules](../docs/project-bootstrap.md#升级已接入项目的规范) 显式升级。升级沿用现有清单结构，受管内容有手工修改时需先整理差异。

M4 的任务请求使用 `schema_version: 1`，沿用 M3 项目的 checks 与 commit_policy。恢复记录属于本机 Git 目录状态，不随业务代码分发；M2 会检测旧提交 Skill，并要求明确保留选择，不自动改写旧文件。

M2 安装清单与事务日志使用 `schema_version: 1`，分别记录资源归属、来源内容指纹与前后快照。安装副本通过 `_toolkit-source.json` 保留来源。通过 GitHub 标签下载并校验的副本还会记录 `release_version`，旧清单可以缺少该字段。更新使用选定的本地来源或 `--version` 指定的正式发行版。业务项目规则通过 `upgrade-rules` 更新，部署工作树快照需按实际状态标识。
