# M2 安装闭环验证记录

日期：2026-11-16。范围：全局规则、生命周期 CLI、安装来源追溯、Skill 链接布局及使用文档。开发和验证只写入临时用户目录与临时业务仓库，未安装到真实用户 home，未修改真实全局规则、config.toml 或旧 Skill，也未推送远程。

## 自动化验证

执行 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`：65 项测试全部通过，包含 M3/M4 的 42 项回归测试及 M2 的 23 项测试。环境为 macOS、Python 3.14.3、Git 2.49.0；其他 Python/Git 版本、操作系统及文件系统未实机验收。

M2 覆盖：

- 预览不创建用户文件；首次安装保留原 AGENTS 字节前缀、原配置和完整运行资源。
- 相同来源重复安装与更新不重写文件、修改时间或创建额外备份。
- 更新保留用户后加的全局前言、末尾内容，保存旧版快照；来源变化需显式 update。
- 卸载保留后续编辑和配置，区分原入口不存在与原空文件，保留恢复备份。
- 同名外来目录、外来 Skill、重复声明同名 Skill、符号链接父目录、受管内容修改、额外文件或空目录、全局区块变更和链接替换均停止自动处理。
- 全局 override、按 name 禁用 Skill、最后匹配的配置条目、旧 git-commit-message 的显式保留选择。
- 入口写入失败时完整回滚；卸载入口失败时恢复原安装；真实子进程强制退出后诊断中断并显式恢复。
- 更新时真实目录已移走但新版未发布的中断间隙，恢复到原版本；恢复遇到用户后续修改、活动进程或不对应的事务时保留现场。
- 独立 CODEX_HOME 与隔离 home，隔离验收不继承真实 CODEX_HOME。
- 清单保留来源 Git 提交与内容指纹；安装副本被手工修改时来源标识为脏快照。
- 原克隆删除后，安装副本仍可执行 M3 初始化与 M4 收尾：实际运行两项业务 unittest，只提交业务功能及测试两个文件；运行 CLI 未在安装副本生成额外字节码缓存，doctor 仍报告部署一致；随后从该安装副本自身执行卸载成功。

Ruff 静态与格式检查通过；两个 Skill 的格式校验通过。新增文档引用与 Git diff 空白检查通过。检验工具通过 uv 临时环境调用，不作为安装器运行依赖。

## 独立 CLI 演练

使用真实命令入口和新的临时 home，依次运行：install 预览、install 应用、doctor、重复 install、update 预览、uninstall 应用、doctor。

观察结果依次为 preview、deployed、deployed、unchanged、unchanged、uninstalled、not_installed。原先不存在的全局入口与两个链接在卸载后消失，操作备份仍保留。此演练使用当前工作树来源，未冒充正式发行版。

## 机制与边界

实现前核对了[官方 AGENTS 机制](https://learn.chatgpt.com/docs/agent-configuration/agents-md)及[官方 Skill 发现机制](https://learn.chatgpt.com/docs/build-skills)，据此使用 Codex home 全局规则和用户 Skill 目录链接。网络 shell 直接读取文档超时后，已通过文档检索服务打开并核对实际页面；没有依赖超时响应推断机制。

部署诊断始终将 `host_loading` 标记为 not_verified。当前没有自动证明真实客户端发现了 Skill、实际读取了新规则或正确选中了工作流；这些必须由用户在新会话完成。项目级、管理员、插件配置与全部宿主加载限制不属于本次静态诊断覆盖。

记录与回滚不保证跨文件系统事务原子性。已测试可捕获错误、子进程强制退出及一个目录切换间隙；没有模拟所有断电、磁盘损坏、对抗性并发、PID 复用或备份损坏组合。日志未形成、锁缺失或临时发布目录无法确认归属时需人工核查，不直接删除或覆盖。显式恢复依赖 POSIX 文件锁，其他平台尚未支持。
