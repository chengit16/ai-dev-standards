# 开发任务收尾

## 入口与策略

本 Skill 随完整 ai-dev-standards 工具包使用；根目录为本文件上两级，先验证 `scripts/finish_task.py` 存在。具体参数、恢复和边界见[收尾使用说明](../../docs/finish-task.md)，请求结构见[任务请求示例](../../templates/finish-task/request.example.json)。缺少工具包资源时定位用户副本，不猜绝对路径或自动安装。

读取当前项目规则与 `.ai-dev-standards/PROJECT.md`、`project.json`，确认本任务已经达到可验收状态。`local` 策略允许必要检查通过后自动本地提交；`manual` 只生成说明和执行已授权检查，用户明确要求本次提交时才应用。当前明确指令优先；“本次不要提交”必须保持不提交。直接调用本 Skill 也不自动授权推送。

## 核对范围与提交说明

- 开始任务时记录 HEAD、已有工作区及暂存状态；收尾时结合本次编辑和完整 diff 判断归属，不能从文件名、时间或“当前全部修改”推断所有权。未记录起点时仍可核实明确独立文件，无法可靠分离则报告阻碍并保留现场。
- 查看状态、暂存与未暂存 diff，以及相关未跟踪文件；diff 禁用 external diff 和 textconv。若存在 `.codegraph/`，理解代码时先用 CodeGraph。未解决冲突或进行中的 Git 操作不进入普通提交流程。
- 请求 `paths` 只列已阅读的精确文件；重命名列出新旧路径，删除列旧路径。使用 `index` 仅选择这些文件中已暂存的内容，可保留同文件的未暂存部分；`worktree` 选择完整文件，遇到部分暂存会停止。不能通过改用 worktree 或整文件 add 来吞入用户改动。同文件混合改动需人工形成准确暂存补丁后复查；无法安全分离则不提交该部分。
- 根据候选净 diff 生成 `<type>: <中文摘要>`，scope、长度和允许类型服从目标仓库。按实际目的选 feat、fix、docs、refactor 等，界面行为不能仅因涉及 CSS 就写 style。正文按需使用中文修改列表，不写已撤回变化、无依据原因或未经验证效果。
- 已初始化项目从采用配置读取全部检查与策略，不在任务请求中覆盖。未初始化项目按实际规则提供 `checks` 和 `commit_policy`。检查清单不足时补齐真实入口并说明缺口，不能用 `true` 或无意义命令冒充验证。请求放仓库外临时文件，避免混入提交。

## 预览、检查与提交

运行 `python3 scripts/finish_task.py task --project <仓库根> --request <请求文件>`，核对输出的完整候选 diff、HEAD 和 tree。仅要求生成提交信息时到此结束，不运行项目命令或提交。执行检查可加 `--check`，其本身不提交。

已授权完成提交时，使用预览中的完整 SHA 添加 `--apply --expected-head <HEAD> --expected-tree <tree>`；manual 下只有已获本次明确提交指令才加 `--authorize-commit`。不重复索取已有授权。工具在检查通过且状态未变化后创建提交，保留其他暂存内容和工作区；不使用 reset、stash、amend 或跳过 hook。检查修改文件或 hook 改写范围时保留现场并按报告复核，不能把失败退出码一概当作“没有提交”。

检查运行于真实工作区。部分暂存或其他修改参与检查时，报告这是工作区检查；按项目要求补充在隔离环境验证候选提交，未执行时明确说明，不能声称提交快照单独通过。检查或提交失败先解决实际问题，禁止绕过检查或 hook。

## 推送与交付

默认停在本地提交。只有用户明确要求推送或项目已明确启用推送策略，才运行独立 `push` 子命令。优先用户指定目标，其次当前 upstream；无 upstream 时核对 pushRemote、pushDefault、唯一远程及同名分支，歧义才询问。不要仅因叫 origin 就猜目标。

先预览目标分支的全部待推送祖先，核实每个提交均获授权，再用 `--allow-commit <完整 SHA>` 逐项列明并加 `--apply`。推送失败保留本地提交；重试只运行 push，不重新 commit。当前实现要求远程查询与推送地址一致且唯一，不设置 upstream，不强推、不自动合并或变基。目标分叉、网络或认证错误时停止。

交付报告提交说明、实际检查及其上下文、SHA、剩余修改和推送结果。根据 `.git/ai-dev-standards/finish-*/report.json` 区分未提交、已提交待复核和已完成；Git worktree 位置以 `git rev-parse --absolute-git-dir` 为准。仅完成脚本测试不等于 Skill 已安装或新会话已加载；这些留待 M2 和用户本机验收。
